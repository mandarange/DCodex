### Cross-cutting resolutions (probes contradicted each other; resolved here, not silently)

- **Source location — Probe 1 vs Probes 2/3/6.** Probe 1 recommended `src/core/gx-mermaid/`. Probe 3 measured that `modulesForGate` (`triwiki-gate-impact-map.ts:81-89`) falls back to `modules = ['release']`, which is **not** a `module_id` in `DEFAULT_TRIWIKI_MODULE_CARDS` (`triwiki-module-card.ts:14-41`), and `'release'` is only added to `affectedModules` when there are zero changed files (`triwiki-affected-graph.ts:53`) — so a gate matching no card is silently dropped. **Decision: all Atlas source lives under `src/core/triwiki/atlas/**`**, which card `triwiki` (`triwiki-module-card.ts:15`, paths `src/core/triwiki/**`) matches with no card edit. This is a sibling of, not inside, `src/core/triwiki/context-graph/**`, so it does not churn the `context-graph:*` gate caches (Probe 5 risk).
- **Gate namespace — Probe 3 (`atlas:`) vs Probe 5 (`architecture:`).** Probe 5's argument was inheritance of `affectedGlobsFor('architecture')` (`gate-manifest.ts:92`) and P0 tier (`gate-manifest.ts:73`). But Probe 5's own risk notes the `architecture:` prefix is automatically P0 while *not* automatically in `ALWAYS_ON_GATES`/`REQUIRED_FOR_PUBLISH` (`gate-manifest.ts:29-71`), so the inheritance is partial. **Decision: `atlas:` prefix, with a mandatory new `case 'atlas':` in `affectedGlobsFor`** — because a prefix with no case falls through to the `default:` at `gate-manifest.ts:170-172`, which returns only `src/scripts/atlas-*.ts` and therefore fires only when the check script itself moves.
- **Passthrough key name — internal to Probe 1.** Probe 1's rationale §4 says top-level `omissions` needs the gx edit; its Step 1 implements a conditional `atlas` key. **Decision: the passthrough key is `atlas`**, and the omission ledger lives inside it (`atlas.omissions`), so one conditional spread covers the ledger and any future top-level Atlas metadata.
- **Where `layer` comes from — Probe 1 vs Probe 5.** Probe 1 derives Mermaid `subgraph` blocks from the existing flat `layer` field (`gx-renderer.ts:58`); Probe 5 defines `layers` as a policy-declared ordering over module node ids. These are compatible only if the Atlas **builder** writes policy-resolved layer names into `node.layer` before normalization. The emitter must never consult the policy file directly.

## Work order amendments

Each item states the original claim as reconstructed from the probe questions, then the corrected text.

**1. Node-kind literals (`wiki_claim`, `risk_domain`, and eight others).**
Original: Atlas gates and views reference node kinds including `wiki_claim` and `risk_domain`.
Corrected: *The production graph published by `sks align run` contains only 4 of the 14 declared node kinds — measured against the real 55,130,387-byte `.sneakoscope/wiki/context-graph.json`: `file 2877, module 118, symbol 21727, test 915` — and 7 edge types: `contains 25519, references 13622, calls 9911, defines 7952, imports 6345, tests 2943, reexports 912`. `command`, `route`, `pipeline`, `gate`, `wiki_claim`, `source`, `proof`, `risk_domain`, `schema` and `config` have zero instances, because align compiles with `codeNavigationGraphExtractors()` (`extractors/index.ts:28`) and hard-asserts a single `code` extractor at `code-navigation-align.ts:323`. ## Unresolved

These need a human decision and cannot be settled from the code.

1. **`htmlLabels` true or false in the rendering target.** `mermaidLabel` cannot be correct for both: with `htmlLabels` on, `&lt;` inside a `"…"` label renders as `<`; with it off, it renders as the literal text `&lt;`. This must be pinned in the module doc comment before A01 writes the escaper — it is a Wave 1 blocker, not a Wave 2 question.
2. **Tracked vs ignored `.mmd`.** Wave 1 receipt #10 settles *whether* byte-determinism holds; it does not settle whether this repo wants to track files derived from an ignored source (`context-graph.json` is ignored at `.gitignore:200`). The precedent is `code-pack.json`, which is tracked and works only because `code-pack-head-freshness` exists to catch the stale-tracked-copy case. Decide before Wave 2 starts.
3. **Does the Mermaid emitter read the Atlas policy at runtime inside an installed `sks` CLI, or only inside repo gates?** This decides whether `loadArchitectureAtlasPolicy` resolves from `process.cwd()` (`check-architecture.ts:178` pattern) or needs a `packageRootDir`-style resolver — and the only such helper is file-local and unexported at `init/skills/manifest.ts:163-167`. Doing both is the wrong answer. Note that `config/architecture-budgets.v1.json` is shipped via `package.json:60` but only ever read from `process.cwd()`, so the shipped copy is currently dead weight; blindly copying that adds more dead weight.
4. **Base32 alphabet: RFC4648-lowercase `[a-z2-7]` or Crockford.** Probe 1 recommends RFC4648 (60 bits in 12 chars, birthday probability ~4e-9 at 100k nodes) since these are machine tokens with a human-readable sidecar map. Either way the work order must **pin** it so the digest is reproducible across implementations.
5. **`cell` level: numeric depth or named tier.** Nothing in the current graph carries it — `depth` exists only on `ContextGraphSelectedNode` (`query-types.ts:78`) as traversal depth from a seed, which is query-relative, not structural. If `cell` must be stable across queries, its definition is Atlas-builder work outside the emitter's scope.
6. **Do the Atlas gates join `ALWAYS_ON_GATES` / `REQUIRED_FOR_PUBLISH` (`gate-manifest.ts:29-71`)?** `architecture:guard` is in both. A topology-drift gate that runs on every publish regardless of changed files has a real cost.
7. **Wave 3: is `$GX` exempt from its own gate?** `routeNeedsEngineeringSanityReview` (`runtime-core.ts:1619`) exempts GX. Since the Atlas is built on the gx-renderer view model, a "GX always runs it" rule collides directly with the pre-existing `$GX` tiny-change overflow measured above.
8. **Wave 3: does the new gate id join the reflection-invalidation exemption at `runtime-gates.ts:539-541`?** Without it, every Atlas-gate failure invalidates reflection and causes the exact verify→rewrite-reflection→re-verify churn the comment at `:536-537` records those exemptions as existing to prevent.
9. **Does `docs:truthfulness` (a release-preset gate) react to new gate ids?** Probe 3 did not read `docs-truthfulness-check.ts` and explicitly listed the docs table row as precedent-convention rather than a verified blocker. Confirm before treating the A00 docs page as optional.
10. **Is a `.sneakoscope/work-orders/architecture-atlas/ownership.json` wanted**, matching the context-graph one (`shared_integration_only` listing `release-gates.v2.json` and `package.json` as integration-only)? If A01–A06 run in parallel, that file is what prevents two workers racing on the manifest.
