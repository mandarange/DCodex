# 8.1.3 Requirement Traceability Ledger

## Status rules and current binding

This ledger uses only these evidence labels:

- **passed-hermetic** — a recorded local test, build, fixture, or gate passed;
  it does not prove a real system.
- **not-run-real** — a required target-bound real artifact has not been
  collected.
- **blocked-external** — the next step needs external authorization or an
  environment outside this checkout.

The integrated 8.1.3 source passed the current local corpus: 2,851 parallel
tests plus 33 resource-sensitive serial tests, 102 Naruto capacity lifecycle
tests, and 50 focused physical/stage/release tests. Exact-commit package and
release receipts are regenerated from the clean handoff commit; older
SHA-bound artifacts are historical only. No row is release authorization
merely because it has `passed-hermetic` evidence.

## Release handoff conditions

1. Commit the integrated source and regenerate exact-commit dist, tarball,
   installation, and package receipts.
2. Collect the explicitly listed real evidence without secrets.
3. Only then perform separately authorized main/tag/staging/publish actions.

The status is **BLOCKED** until all required source-bound and real evidence is
current. This ledger intentionally makes no claim that a live provider, OAuth
profile, native UI, launchd service, WebSocket exchange, or deep feature has
passed.
