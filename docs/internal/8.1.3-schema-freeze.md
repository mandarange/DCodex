# 8.1.3 Desktop Bridge Schema Freeze

## Authority

The work order is the product authority. The compile-time facade is `src/core/codex-lb/bridge-contracts.ts`. Parallel streams may add implementation-private fields, but must not rename, weaken, or reinterpret these public contracts without returning the change to the integration owner.

## Frozen Runtime and Identity Rules

- Managed runtime constant: `desktop-bridge` only.
- Runtime states: `not_installed`, `starting`, `ready`, `degraded`, `blocked`, `stopped`, `stale`.
- Unmanaged reasons: `uninstalled`, `rollback_complete`, `never_configured`.
- Provider IDs: `codex-lb`, `openrouter`.
- ChatGPT OAuth is a Codex-owned native identity prerequisite, not a provider profile or bridge credential.
- Provider enable/disable, credential removal, catalog state, route selection, and runtime lifecycle are separate state transitions.

## Frozen Routing Rules

- `BridgeRoutingPolicy.schema` is `sks.bridge-routing-policy.v1`.
- `fallback` is always `none`.
- Every request resolves through an explicit canonical-model route or a validated session pin.
- Model slashes, old mode strings, or provider order must never choose a route.
- Ambiguous public IDs produce `catalog_model_route_ambiguous`; unknown IDs produce an explicit missing-route blocker.
- `ProviderSessionPin` binds provider, public/upstream model, catalog generation, and route-policy generation.

## Frozen Catalog Rules

- Provider catalog state is `sks.catalog-sync-state.v2`.
- Combined state is `sks.combined-catalog-sync.v1`.
- Route index is `sks.bridge-route-index.v1`.
- Catalog and route index generations are deterministic for identical canonical input and activate atomically.
- A failed build preserves the previous verified generation.
- Status objects contain credential fingerprints only, never secrets.

## Frozen Capability Rules

- Probe schema: `sks.capability-probe.v3`.
- Report schema: `sks.desktop-capabilities.v3`.
- Requested levels: `shallow`, `transport`, `deep`.
- Scope is one of bridge, native identity, Codex-LB provider, OpenRouter provider, or combined catalog.
- `not_attempted` is not a blocker; stale evidence is never verified.
- A probe path has at most one terminal root cause.
- Execution success and readiness are independently representable.
- An inactive provider or a deep-only feature cannot globally block an otherwise ready route.
- The frozen `ScopeCapabilitySummary` groups exact v3 results by capability so CLI and Swift decode one deterministic facade.

## Frozen Transport Rules

- HTTP probe schema: `sks.desktop-bridge-http-probe.v1`.
- WebSocket probe schema: `sks.desktop-bridge-websocket-probe.v2`.
- WebSocket upgrade, protocol negotiation, frame round trip, and clean close are separate facts.
- `desktop_bridge_websocket_transport_failed` is forbidden as a terminal blocker.
- Provider-specific HTTP and WebSocket header policies strip incoming OAuth and select exactly one provider credential.
- Origin, path, route-index membership, and session pin are validated before credential resolution.

## Frozen Migration Rules

- Receipt schema: `sks.desktop-bridge-unification-receipt.v1`.
- Baseline/target versions are `8.1.2` and `8.1.3`.
- `credentials_deleted` is always false.
- New managed config writes `model_provider="openai"`, a managed loopback `openai_base_url`, and the single combined catalog path.
- Rollback restores config/runtime/catalog/route/launchd metadata only. It must not overwrite current provider credentials or Codex OAuth state.
- Re-running the migration on identical input is a byte-for-byte no-op.

## Deliberate Facade Decisions

The work order names but does not spell out `ScopeCapabilitySummary`, `ProviderCapabilitySummary`, and `HttpProbeResult`. Wave 0 freezes the smallest cross-consumer shapes needed by controller, CLI, and native UI:

- a scope summary has scope, state, checked time, keyed v3 results, blockers, and warnings;
- provider capability summary is the same scope summary contract;
- HTTP probe records only TCP/HTTP/complete terminal stage, one root cause, status, latency, blockers, and warnings.

Implementations must place extra diagnostics in probe evidence or private result types rather than silently changing the facade.

## Compatibility Boundary

Old desktop/provider modes, v2 capability output, and legacy CLI aliases may survive for one patch version only as adapters or migration inputs. Active runtime modules must not import legacy parsers after integration.
