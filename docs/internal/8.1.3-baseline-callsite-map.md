## Integration Seams

1. `bridge-contracts.ts` is the frozen cross-stream facade.
2. Config/migration writes the single bridge binding and a receipt.
3. Registry/catalog resolves two provider profiles, deterministic route index, and atomic catalog generations.
4. Bridge transport consumes registry/policy snapshots and applies route-specific credentials without forwarding OAuth.
5. Capability v3 consumes structured HTTP/WebSocket results and reports scope-local truth.
6. The parent integrates those surfaces in `desktop-controller.ts` and `routing-truth.ts`.
7. CLI and native UI consume the v3 facade and never infer truth from old mode strings.

## Added Scope: Naruto Capacity Admission

- `src/core/subagents/official-subagent-config.ts` currently clamps an over-cap repository setting for arithmetic but also emits `*_exceeds_hard_cap` as a hard blocker.
- A repository preference such as `max_threads=1000` can therefore block admission even with zero active children and an 8-agent request.
- The fix will preserve the user setting, normalize effective child/total capacity to 256/257, emit a warning, and retain strict rejection only for an explicit CLI `--agents` or `--max-threads` request above 256.
